# Data Model: RetroSocial MVP

**Branch**: `001-retrosocial-mvp` | **Date**: 2026-07-06 | **Phase**: 1

---

## Firestore Collections

### Collection: `users`

One document per registered user. Document ID equals the Firebase Auth UID.

| Field | Type | Required | Constraints | Notes |
|---|---|---|---|---|
| `uid` | `string` | ✅ | Equals document ID | Redundant but useful for queries |
| `username` | `string` | ✅ | Unique platform-wide; non-empty | Checked via transaction on registration |
| `email` | `string` | ✅ | Valid email format | Mirrors Firebase Auth email |
| `createdAt` | `timestamp` | ✅ | Server timestamp | Set once at registration; never updated |

**Indexes**: A composite index on `username` (ascending) is required to support uniqueness queries. Firebase auto-indexes single fields; this is sufficient.

**Lifecycle**:
- Created: atomically during `registerUser` after `createUserWithEmailAndPassword` succeeds.
- Updated: not in scope for MVP (no profile editing).
- Deleted: not in scope for MVP.

---

### Collection: `posts`

One document per post. Document ID is auto-generated by Firestore.

| Field | Type | Required | Constraints | Notes |
|---|---|---|---|---|
| `type` | `string` | ✅ | `'text'` or `'photo'` only | Determines which content field is populated |
| `content` | `string \| null` | ✅ | ≤ 100 chars if type=`text`; `null` if type=`photo` | Plain text; no HTML or Markdown |
| `imageUrl` | `string \| null` | ✅ | Valid HTTPS URL if type=`photo`; `null` if type=`text` | Firebase Storage download URL |
| `authorId` | `string` | ✅ | Equals Firebase Auth UID of creator | Used for ownership checks |
| `authorUsername` | `string` | ✅ | Non-empty; denormalised from `users` doc | Stored at creation; not updated if username changes |
| `createdAt` | `timestamp` | ✅ | Server timestamp | Set once at creation |
| `updatedAt` | `timestamp \| null` | ✅ | Server timestamp or `null` | `null` at creation; set on each edit |

**Invariants**:
- `type === 'text'` → `content` is a non-empty string ≤ 100 chars AND `imageUrl` is `null`.
- `type === 'photo'` → `imageUrl` is a non-empty string AND `content` is `null`.
- These invariants are enforced by both the client and Firestore Security Rules.

**Indexes**: Default index on `createdAt` (descending) for feed query. Firebase auto-creates single-field indexes; no manual index required for the MVP feed.

**Lifecycle**:
- Created: via `createTextPost` or `createPhotoPost` service functions.
- Updated: via `updateTextPost` (text only) or `replacePostImage` (photo only). `updatedAt` set to `serverTimestamp()`.
- Deleted: via `deletePost`. If `imageUrl` is set, the corresponding Storage object is also deleted.

## Firebase Storage

### Path Structure

```
posts/{authorId}/{postId}
```

- `authorId` — Firebase Auth UID of the post author (enables ownership-based Storage rules).
- `postId` — The Firestore document ID generated client-side before upload begins.

### File Constraints (enforced in Storage Rules and client validation)

| Constraint | Value |
|---|---|
| Allowed MIME types | `image/jpeg`, `image/png`, `image/gif`, `image/webp` |
| Maximum file size | 5 MB (5 × 1,048,576 bytes = 5,242,880 bytes) |

### Object Lifecycle

- **Created**: during `uploadImage(authorId, postId, file)` using `uploadBytesResumable`.
- **Replaced**: during `replacePostImage` — new upload to the same path overwrites the existing object.
- **Deleted**: during `deletePost` if the post has an `imageUrl` — `deleteObject(ref(storage, 'posts/{authorId}/{postId}'))`.

## Firestore Security Rules

```firestore
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // ── users collection ──────────────────────────────────────────────────
    match /users/{userId} {
      // Any authenticated user can read user documents (e.g., username lookup).
      allow read: if request.auth != null;

      // Only the owner can create their own user document.
      allow create: if request.auth != null
                    && request.auth.uid == userId
                    && request.resource.data.username is string
                    && request.resource.data.username.size() > 0
                    && request.resource.data.email is string;

      // Only the owner can update their own user document (not in scope but permitted).
      allow update: if request.auth != null
                    && request.auth.uid == userId;

      // Deletion not permitted.
      allow delete: if false;
    }

    // ── posts collection ──────────────────────────────────────────────────
    match /posts/{postId} {
      // Any authenticated user can read posts.
      allow read: if request.auth != null;

      // Creation: authenticated + authorId matches caller + type-specific field rules.
      allow create: if request.auth != null
                    && request.resource.data.authorId == request.auth.uid
                    && request.resource.data.authorUsername is string
                    && request.resource.data.authorUsername.size() > 0
                    && request.resource.data.createdAt == request.time
                    && request.resource.data.updatedAt == null
                    && (
                         // Text post invariant
                         (
                           request.resource.data.type == 'text'
                           && request.resource.data.content is string
                           && request.resource.data.content.size() > 0
                           && request.resource.data.content.size() <= 100
                           && request.resource.data.imageUrl == null
                         )
                         ||
                         // Photo post invariant
                         (
                           request.resource.data.type == 'photo'
                           && request.resource.data.imageUrl is string
                           && request.resource.data.imageUrl.size() > 0
                           && request.resource.data.content == null
                         )
                       );

      // Update: only owner; authorId must not change; type-specific invariants apply.
      allow update: if request.auth != null
                    && resource.data.authorId == request.auth.uid
                    && request.resource.data.authorId == request.auth.uid
                    && request.resource.data.type == resource.data.type
                    && (
                         (
                           request.resource.data.type == 'text'
                           && request.resource.data.content is string
                           && request.resource.data.content.size() > 0
                           && request.resource.data.content.size() <= 100
                           && request.resource.data.imageUrl == null
                         )
                         ||
                         (
                           request.resource.data.type == 'photo'
                           && request.resource.data.imageUrl is string
                           && request.resource.data.imageUrl.size() > 0
                           && request.resource.data.content == null
                         )
                       );

      // Delete: only owner.
      allow delete: if request.auth != null
                    && resource.data.authorId == request.auth.uid;
    }
  }
}
```

## Storage Security Rules

```storage
rules_version = '2';

service firebase.storage {
  match /b/{bucket}/o {

    // Images stored under posts/{authorId}/{postId}
    match /posts/{userId}/{postId} {
      // Any authenticated user can read (view) images.
      allow read: if request.auth != null;

      // Write (create or replace): caller must own the path,
      // file must be ≤ 5 MB, and MIME type must be a supported image format.
      allow write: if request.auth != null
                   && request.auth.uid == userId
                   && request.resource.size <= 5 * 1024 * 1024
                   && request.resource.contentType.matches('image/(jpeg|png|gif|webp)');

      // Delete: only the owner of the path.
      allow delete: if request.auth != null
                    && request.auth.uid == userId;
    }
  }
}
```

## Entity Relationship Summary

```
User (users/{uid})
  uid            PK = Firebase Auth UID
  username       UNIQUE
  email
  createdAt

Post (posts/{postId})
  postId         PK = Firestore auto-ID
  type           'text' | 'photo'
  content        string | null    (text posts only)
  imageUrl       string | null    (photo posts only)
  authorId       FK → User.uid
  authorUsername denormalised from User.username
  createdAt
  updatedAt
```

A `User` may have zero or more `Post` documents. A `Post` belongs to exactly one `User`. The relationship is maintained via `authorId`; referential integrity is enforced by the ownership rules (a post cannot be created with an `authorId` that differs from the caller's UID).
